# Full review — 2026-11-24

Three independent reviews (security, QA of every operation, UX/marketing) were run in parallel against the code;
every finding below was verified in the code before being acted on.

## Fixed in this pass
| Area | Finding | Fix |
|---|---|---|
| Security | Registration had **no throttle and no honeypot**: `getByName()` returned null before name lookups were indexed, and `?->` hid it | `refreshNameLookups()` + fail loudly if the route is missing; route now shows `throttle:5,1` + `ProtectAgainstSpam` |
| Security | Honeypot could be bypassed by omitting its fields | `config/honeypot.php` published with `honeypot_fields_required_for_all_forms = true` |
| Security | Deactivated users kept their existing sessions | `EnsureUserIsActive` middleware signs them out on the next request |
| Security | E-mail change without the current password (session hijack → password reset takeover) | `current_password` required when the e-mail changes |
| Security | POS pages could be stored by shared caches | `Cache-Control: no-store` on `pos.*` |
| Security | Catalog seeder wrote description HTML unsanitized | `RichText::clean()` like every other write path |
| Security | Image downloader fetched any URL (SSRF if data is tampered) | HTTPS + `WOO_BASE_URL` host only, no redirects |
| Orders | Cancelling an order that sold a variant out left it **unsellable** (status stayed out-of-stock; caches not flushed) | Restock through Eloquent, back to *in stock*, observer flushes caches |
| Orders | Double cancel could restock twice (status checked outside the lock) | Status re-read under `lockForUpdate()` inside the transaction |
| Cart | A deleted product in a cart made cart and checkout return 500 | Orphaned lines are dropped when the cart is resolved |
| Admin | Admins could deactivate / demote themselves; a super-admin edit stripped the super-admin role | Self-deactivation rejected, own roles locked, super-admin preserved |
| Money | The currency setting was ignored when formatting (always ILS) | `Money` defaults to the store currency setting |
| UX | See `ui-ux-system.md` → "Marketing & readability pass" | — |

## Marketing roadmap (not built yet — needs the owner's decisions)
Ranked by impact for a marketing-driven store in this market:
1. **Coupons / promo codes** (percent, fixed, free delivery, min order, usage limits, expiry; optional company scope). `discount_total` already exists on orders. *M*
2. **Ad pixels & analytics** (Meta Pixel, GA4/GTM, TikTok): IDs in admin settings, CSP allow-list per vendor, events ViewContent / AddToCart / InitiateCheckout / Purchase; store UTM/source on orders. Needs a cookie-consent banner. *M*
3. **Order on WhatsApp** from cart (prefilled items + total) and a WhatsApp confirmation link on the thank-you page (product page "ask on WhatsApp" is done). *S*
4. **Customer notifications**: order confirmation / status updates by SMS or WhatsApp Business API (needs a provider account). *M*
5. **Campaign banners**: announcement bar + multi-slide hero with schedule and per-locale content from admin. *M*
6. **Wholesale / B2B pricing** that the old site had (price list or % per company, quantity tiers) for POS and approved accounts. *M–L*
7. Reviews & ratings (+ `aggregateRating`), newsletter/lead capture, abandoned-cart reminder, guest order tracking, wishlist, back-in-stock alerts, share buttons. *S–M each*
